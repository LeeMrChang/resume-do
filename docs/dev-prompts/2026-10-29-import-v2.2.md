# 开发任务：简历导入 v2.2 整改（导入直落编辑界面）

> 需求依据：Notion「📥 简历导入 · 需求说明 v2.2」页（id `407a36e1-ae8a-8177-9261-d721e53b0853`）
> 目标仓库：resume-do
> 本次性质：**删逻辑为主，不是新增系统**。当前导入后落在「原件预览」视图，用户无法进入编辑，等同于导入无效。

---

## 一、最高优先级：导入后直落编辑界面

**现状**：导入成功 → 创建 `kind=original` 简历 → 落到原件预览（`OriginalResumeView`），顶部只有「返回编辑器 / 新建可编辑简历」按钮。用户必须手动再走一步才能编辑。

**要求**：
1. 导入解析成功后，**直接创建可编辑简历并跳转到编辑界面**，各模块（基本信息 / 求职意向 / 教育 / 工作 / 项目 / 技能 / 自我评价）**已用解析结果回填**，用户落地即可改。
2. 取消「转为可编辑」这个中间动作，编辑界面就是导入的终点。
3. 原件不丢：原 PDF/DOCX 与这份可编辑简历**建立关联**（一份导入 = 原件 + 可编辑两个视图态）。
4. 编辑界面顶部提供 **「查看原件」** 入口，随时切到 PDF.js 原件预览；原件视图顶部保留 **「返回编辑器」**。两视图双向可达，**不允许任何死胡同视图**。
5. 切换简历下拉里的命名成对出现：`2026-李昌浩 · 原件` / `2026-李昌浩 · 可编辑`。

**涉及文件**：
- `apps/web/src/EditorPage.tsx`（`resumeList` / `activeResumeId` / `kind` 分流、顶部按钮区）
- `apps/web/src/ImportDialog.tsx`、`apps/web/src/importDraft.ts`（导入成功回调 → 跳编辑器）
- `apps/web/src/OriginalResumeView.tsx`（只作「查看原件」用，不再是导入落点）
- `apps/web/src/OriginalImportButton.tsx`
- 后端 `apps/api/src/main/java/com/resumedo/importing/`（`ImportService.confirm` 需同时落原件与可编辑简历，并返回可编辑简历 id）

---

## 二、导出弹窗：原件版 / 编辑版双选项

**要求**：`Dialogs.tsx` 的导出弹窗改为两个选项，并列展示并注明差异：

| 选项 | 行为 | 默认 |
| --- | --- | --- |
| **原件版** | 直出导入的原文件，内容 100% 与原件一致（零解析损失） | ✅ 默认选中 |
| **编辑版** | 按当前模板与数据渲染（现有 export 链路） | 用户改过内容后建议提示切换 |

- 未做任何修改时，「编辑版」导出内容应与「原件版」一致（版式差异除外）。
- 复用现有 `ExportService` 任务模型，原件版走单独分支（直接回源文件），不要新造一套任务体系。

---

## 三、解析质量修复（必做，否则页数虚增）

1. **禁止内容重复**：结构化字段（学校/公司/职位/起止时间）提取成功后，正文**不得再包含原始行**。当前每条教育/工作都重复两遍，直接导致 3 页变 4 页。
2. 「待整理内容」机制保留：只有真正解析失败的段落才整体进正文或待整理区，正常简历应零待整理。
3. **页数口径**：原件版页数必须 = 原文件页数（不一致即 bug）；编辑版不得因重复内容虚增页数，且无空白尾页、无裁切、无孤立标题。

---

## 四、保真增强

**IMP-F1 照片提取**
- 从 PDF 提取内嵌证件照（`pdfimages` 类方案 / PDF 图片对象），从 DOCX 提取内联图片。
- 多图时取尺寸最大/位置最前者，其余进待整理；提取失败**不阻断导入**。
- 回填的照片同样受基本信息的「展示照片」开关控制。

**IMP-F3 基本信息字段扩展（P0）**
- 新增：`出生年月`（自动计算年龄展示）、`籍贯`、`民族`、`婚姻状况`、`政治面貌`、`身高体重`。
- 其余非常规字段走既有「自定义键值对」承接，不丢信息。
- 同步扩展 `packages/schema` 的类型定义与后端 `ResumeValidator` 校验。

**「展示照片」开关**
- 默认开启；关闭后预览与导出 PDF 均不含照片，数据保留；无照片/不展示时头部布局自动收起不破版。

## 五、验收自测清单（交付前逐条过）

1. 导入「2026-李昌浩.pdf」→ **直接落在编辑界面**，基本信息/教育/工作/项目/技能/自我评价均有值，无需任何中间表单。
2. 教育与工作经历**无重复正文**；预览页数不因重复内容增加。
3. 顶部「查看原件」能打开原件 PDF（页数与原文件一致，3 页就是 3 页），可返回编辑器。
4. 导出弹窗两个选项可用；默认原件版，导出的 PDF 与原文件内容一致；编辑版在未修改时内容一致。
5. 照片已回填到基本信息；勾掉「展示照片」后预览与导出均无照片且不破版。
6. 出生年月/籍贯/民族/婚姻/政治面貌/身高体重有值；原件其他字段进自定义键值对。
7. 刷新页面数据仍在；切换简历下拉里「原件 / 可编辑」两态都在，切换不丢数据。

## 六、工作量拆分（建议两批交付）

**第一批 · 热修（0.5~1.5 天，先解除痛点）**
- 导入成功后跳过强制校对，直接确认并跳编辑界面；`ImportDialog.onConfirmed` 已返回简历对象，只需在 `EditorPage` 打开它
- 顶部加「查看原件」入口（`resumes` 表 V3 已有 `source_key/source_filename/source_pages` 字段，关联基建现成）
- 导出弹窗加「原件版」选项（复用 `source_key` 直出文件）

> 结论：**前端为主，后端几乎不动**。`ImportService.confirm` 已经用解析草稿 `resumes.create(...)` 并返回简历，链路是通的，缺的只是「不弹校对表单 + 落点改向 + 原件关联展示」。

**第二批 · 保真增强（4~6 天）**
| 项 | 估时 | 说明 |
| --- | --- | --- |
| 解析去重复（V03） | 1~2 天 | `ImportMapper` 158 行，需重构字段与正文的边界判定 + 回归用例 |
| 照片提取（IMP-F1） | 1~2 天 | Java 侧用 PDFBox 抽 `PDImageXObject`，难点是「哪张是证件照」的启发式（尺寸/位置/面积占比） |
| 字段扩展（IMP-F3） | 2~3 天 | schema 类型 + `ResumeValidator` + 表单 UI + 模板渲染 + 解析映射，五处联动 |
| 验收回归（长简历/分页/双版导出） | 1 天 | — |

## 七、边界（不要做的事）

- 不接入任何外部 AI 解析服务（登录页承诺「不发送到第三方」）；「智能解析」开关维持默认关闭，本期不实现。
- 不做 PDF 像素级版式复刻（L3 不进需求）。
- 不改动 LIS 列表页、暗黑风格相关代码（属另外两条任务线）。
- 原件与可编辑简历的删除需提示两者关系，避免只删一半造成孤儿数据。
