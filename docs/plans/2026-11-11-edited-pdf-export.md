# 当前编辑版 PDF 导出调整

依据：AGENTS.md、既有导出链路和用户对导出弹窗的要求。旧导入设计中的默认原件版选项由本次需求替代。

## 方案

编辑器中的下载 PDF 只导出当前编辑内容与模板。弹窗先显示文件名、A4 纸张和预览页数，点击下载后保存最新修改并固定 revision，沿用现有异步任务、进度查询、自动下载和重试。移除原件/编辑版选择。排版使用现有深浅主题变量，支持窄屏和长文件名。

原件查看和历史只读原件下载继续保留；不修改后端接口、原件存储和共享 PDF 模板。

## 执行与验证

1. 补充浏览器回归测试，先确认旧实现未通过：有 PDF 原件仍导出编辑内容、无原件与 DOCX 行为统一；保存失败不导出；生成失败可重试，下载失败可再次下载。
2. 调整 ExportDialog 状态与布局，更新调用方；防止重复提交，保留失败提示。
3. 更新导入回归、README 和接口说明中的前端使用说明。
4. 执行类型检查、前端测试和构建，再运行浏览器导出及导入回归；检查深浅主题、窄屏及长文件名。API 使用内存 mock，不触碰真实账号和数据库。
5. 检查 diff，交付分支与验证结果；不提交、不推送、不部署。

## 后续调整：导入文件名自动填入简历名称

用户要求继续在同一分支修改：导入 PDF / DOCX 成功后，顶部简历名称使用文件名去掉末尾扩展名，刷新后保留。

原因：ImportMapper 已生成文件名标题，但覆盖导入调用的 replaceImported 没有更新 title 列，导致保留“我的简历”或旧名称。

实施：先把既有服务回归的预期名称改为新文件名，实际运行得到 expected 新简历 / actual 旧简历的失败；再将名称加入覆盖导入的同一次 SQL 更新。沿用既有文件名清洗、扩展名去除与 100 字限制，不新增记录、不修改 ID。同步更新导入浏览器回归、README 和 API 说明。

验证：OriginalResumeServiceTest 与 ImportMapperTest 共 34 项通过（Failures 0 / Errors 0）；前端类型检查通过。浏览器回归已补充名称与刷新后名称断言，未在本环境实际完成浏览器验收。此项修改需要重新启动 Java API 后重新导入生效；不批量修改此前已导入的简历。
